# 员工薪酬与社保公积金配置实施计划

日期：2026-11-09

本次任务为制定变更计划；不修改业务代码或本机主体数据。产品行为以《社保公积金基数与比例变更计划.md》为依据。本文件将其拆为开发与验收任务。工作区检查时无已有未提交变更。

## 当前实现与目标差距

- 工资方案已有手工保存、导入和有效期冲突检查，但使用日级日期；员工档案仍保存固定月薪，需要收敛为唯一方案来源。
- 社保导入和计算仍以员工承担、单位承担金额为输入，尚未接入按项目的基数与比例配置。
- 员工页面目前通过弹窗维护资料与工资方案，需要增加月份查询、逐行展开及三类配置历史。
- 单人计算、整批计算、工作进度判断及规则输入均引用承担金额，需要统一改用配置解析结果，避免遗漏旁路。

## 分阶段实施

## 数据契约与规则

- 工资方案：员工、固定月薪、开始月份、结束月份、来源及备注；区间包含首尾月，结束为空表示持续有效。
- 主体默认：缴费项目、启用状态、有效月份区间、可空默认基数与双方比例、版本及来源。
- 员工覆盖：员工、项目、有效月份区间、可空基数与双方比例、版本及批次来源；至少覆盖一个字段。
- 金额和比例使用十进制；界面百分数 2.5 表示 2.5%。基数必须为正，比例范围为 0%–100%，这些是软件输入约束，不代表地方政策。
- 启用项目逐字段解析：员工有效覆盖 → 主体有效默认 → 缺失阻断。项目启用状态由主体配置决定，禁用项目不要求基数比例，也不计入金额。
- 同一主体项目、同一员工项目分别禁止有效区间重叠；工资方案独立校验。新增后续记录不得静默截断旧记录。
- 快照保存最终值、各字段来源、配置版本、逐项金额及汇总。旧快照缺少配置字段时保留“旧版金额结果”标识，不补造数据。
- 配置变更仅影响新试算；批量计算先验证全体参算人员，再以事务保存整批版本，失败不得产生部分结果。

## 重点验收

1. 全员默认、仅覆盖基数、仅覆盖一方比例、清除覆盖四种路径正确；0% 不回退默认。
2. 工资 7 月调整、基数 8 月调整，分别验证 6、7、8 月；所属月与发放月不同时仍按所属月选择。
3. 基数 10000、员工 2.5%、单位 5% 得到 250 和 500；另设多项目小数场景验证逐项舍入与汇总。
4. 缺失、重叠、重复导入、非法月份及未知员工均有可定位错误；整批缺一人配置时无部分保存。
5. 撤销导入后重新解析默认；恢复若与新建配置冲突则拒绝恢复，不留下重叠有效数据。
6. 单人与整批金额一致；规则不能覆盖或重复累加系统承担金额；配置变化能触发重新试算提示。
7. 升级及备份恢复保留主体配置、覆盖记录、批次与旧快照；旧金额批次不参与新计算。
8. 相同金额但不同基数比例显示金额一致与配置变化；未知税额或实发保持不完整状态。

## 手动验收反馈调整（0.3.15）

按用户最新要求，工资方案与社保公积金配置新增直接编辑，包括导入记录。工资保存和导入按月校验相邻方案不得重叠或存在内部断档。导入记录的编辑值与原批次关联，撤销后不生效，恢复时对编辑后的有效期进行冲突检查。员工行编辑与“维护员工覆盖”只创建或变更员工自定义配置，主体默认仅作参考；主体设置仍是修改全员默认值的独立入口。员工覆盖弹窗显示已有主体默认及员工配置，允许修改基数、比例和有效月份，未覆盖字段继续继承。历史计算快照不随这些修改重写。

新增实时匹配的重算标记：读取结果时将快照中的工资方案、缴费基数比例、来源及输入规则与当前所属月的有效资料核对，差异或配置缺失即标记“需要重新计算”。此标记只用于返回界面，不回写历史快照；受影响月份之外的结果保持原状态。
