# 员工工资、社保公积金基数与比例变更计划

日期：2026-11-06。基于当前 0.3.12 源码制定，本轮只形成计划，不修改业务实现。

## 1. 已确认的方向

- 员工工资方案、社保基数与比例、公积金基数与比例统一在“员工与薪酬方案”Tab 维护。
- 员工主表支持逐行展开，在员工行下查看工资方案列表、社保配置列表和公积金配置列表，包含历史、当前及未来生效记录。
- 工资方案和缴费配置均设置开始、结束时间；本计划按月份维护有效期，计算按工资所属月份匹配，不按计划发放月匹配。


- 取消直接录入或导入员工承担、单位承担金额。所有新计算均使用“有效基数 × 有效比例”。
- 主体增加独立的“主体设置 → 社保公积金默认配置”入口，保存默认基数和比例；员工手工维护或导入有效特殊配置时，按字段覆盖主体默认值。
- 员工与薪酬方案页显示当前月份最终采用的基数和两方比例；员工未设置的字段直接显示主体默认值，并明确标注“跟随主体默认”，不留空或默认显示为 0。
- 按上年度平均工资核定的公司，导入每位员工已核定的基数及其有效期间。有效期内复用，不必每月重传；没有统一基数时可不填主体默认基数。
- 基数不自动跟随当月绩效或应发变动。本次不自动核算上年度平均工资；已核定基数由业务提供。
- 社保各项目与公积金分别配置基数和员工、单位两方比例。
- 比例按缴费项目分别设置员工、单位两方；支持主体默认和员工特殊比例。

## 2. 统一采用主体默认与员工覆盖

不增加额外模式开关。每个缴费项目、每个字段分别按以下顺序取值：

**员工在当期有效的覆盖值 → 主体在当期有效的默认值 → 两者均缺失则阻止计算。**

| 场景 | 主体设置 | 员工导入 | 实际采用 |
| --- | --- | --- | --- |
| 全员统一 | 默认基数和两方比例 | 无需导入 | 主体默认值 |
| 少数员工基数特殊 | 默认基数和两方比例 | 特殊员工的基数、有效期间 | 特殊员工采用覆盖基数，比例跟随主体；其他人全部跟随主体 |
| 少数员工比例特殊 | 默认基数和两方比例 | 特殊员工某项目的一方或两方比例、有效期间 | 已填写的比例覆盖默认，其余字段跟随主体 |
| 各员工按上年平均工资核定 | 默认比例，统一基数可留空 | 每人核定基数、有效期间，比例仅在特殊时填写 | 每人基数加员工覆盖或主体默认比例 |

主体默认值和员工覆盖值均按有效期间维护；后续调整不覆盖历史配置或已保存结果。未填写是“跟随默认”，明确填写 0% 是“采用零比例”。

## 3. 员工行展开与配置维护

### 主体设置入口

- 在当前主体选择菜单中增加“主体设置”，进入该主体的“社保公积金默认配置”。主体列表可提供同一设置入口，未解锁时先解锁目标主体。
- 设置页按社保项目、公积金分别维护默认基数、员工缴费比例、单位缴费比例、是否启用、开始月份和结束月份。
- 默认配置按主体独立保存；切换主体后只读取目标主体配置。不能编辑其他未解锁主体的配置。
- 员工与薪酬方案页的“主体默认缴费配置”按钮打开同一设置功能，不再维护另一份默认值。
- 主体设置显示当前、历史与未来生效配置；保存后自动刷新当前员工页的继承显示，并对受影响期间提示需要重新试算，不改写已保存快照。

### 统一页面入口

“员工与薪酬方案”Tab 顶部保留姓名/工号搜索、人员类型和新增员工，并增加“查看月份”条件，以及“主体默认缴费配置”“导入工资方案”“导入基数与比例”入口。条件变化后自动刷新，可手动重新查询；选择框与蓝色操作按钮同高对齐。

员工主表显示姓名、工号、部门，以及查看月份对应的工资、社保基数、公积金基数和配置完整状态；比例在对应项目的展开列表中完整显示。员工姓名优先显示，工号用于区分同名人员。多缴费项目基数不同时显示“按项目”，展开查看明细，不误用单一金额概括。

每名员工支持独立展开，展开区域包含：

| 列表 | 主要字段 | 操作 |
| --- | --- | --- |
| 工资方案列表 | 固定月薪、开始月份、结束月份、来源、备注、生效状态 | 新增、查看、调整后续期间 |
| 社保基数与比例列表 | 缴费项目、基数、员工比例、单位比例、开始/结束月份、配置来源、生效状态 | 新增或维护员工覆盖配置、查看主体默认 |
| 公积金基数与比例列表 | 缴费基数、员工比例、单位比例、开始/结束月份、配置来源、生效状态 | 新增或维护员工覆盖配置、查看主体默认 |

- 各列表展示历史、当前和未来记录，按开始月份倒序；明确标注“当前生效”“尚未生效”“已结束”。
- 当前生效的配置展示最终采用值；继承项标明“跟随主体默认”，员工覆盖项标明“员工单独设置”。
- 员工未设置任何有效缴费配置时，展开列表直接显示当期主体默认基数和比例；不是只显示“未配置”。
- 继承按基数、员工比例、单位比例逐字段处理。例如员工只设置特殊基数，比例列仍显示主体默认员工比例和单位比例。
- 主体默认和员工覆盖均缺失时，显示“未配置”及补齐入口，不显示虚构金额或比例；明确填写的 0% 正常显示，不视为缺失。
- 继承行不生成重复员工配置。用户点击新增或修改员工配置后才创建员工覆盖记录；清除某个覆盖字段后恢复显示主体默认值。
- 更换查看月份时，基数、比例及来源标识一并重新匹配；已结束的员工覆盖记录不能影响其他月份。
- 工资方案列表保存约定固定月薪和有效期，不混入计算结果版本；当月绩效、考勤、补发补扣仍来自原有当期输入。
- 手工维护与导入写入同一套业务记录，不能产生两套互不一致的工资或基数列表。
- 数据导入页可以保留通往同一导入功能的快捷入口；员工列表是查询和维护工资、基数、比例的统一入口。

### 工资方案与时间匹配

- 每条员工工资方案维护固定月薪、开始月份、结束月份（可留空）、来源和备注。
- 开始月份与结束月份均包含当月。例如 `2026-01` 至 `2026-06` 覆盖 1–6 月，下一条从 `2026-07` 开始。
- 同一员工同一所属月份只允许一条有效工资方案；重叠阻止保存或导入，缺失阻止计算，不取最近一条或按 0 处理。
- 工资、社保、公积金的有效期独立。例如工资 7 月调整、缴费基数 8 月调整，7 月分别匹配新工资与旧基数。
- 未填结束月份表示持续有效；新增后续方案时，提示先衔接上一条的结束月份，确认后保存，不能静默覆盖整段历史。
- 本次以月为粒度，不自动将月中日期解释为整月，也不隐含新增按天分段计薪；旧数据中的月中生效情况明确提示处理。

### 主体配置

- 按缴费项目设置默认基数及两方比例；没有统一基数时允许默认基数留空，但参算员工必须有完整有效配置。
- 项目表分别维护员工比例、单位比例及是否启用；社保分项目维护，公积金独立维护。
- 使用生效月份、截止月份（可留空）管理版本，以工资所属期匹配配置。
- 同一主体、同一项目、同一期间只允许一份有效配置；重叠时明确报错。
- 比例界面统一填写百分数，例如 `2.5` 表示 `2.5%`；不要求用户填写 `0.025`。
- 使用十进制数保存金额和比例；0% 是明确有效值，空值表示未配置或跟随默认，两者区分。

### 员工特殊配置

- 可分别覆盖社保各项目和公积金的基数。
- 可只覆盖某个项目的员工比例或单位比例，未覆盖的一方继续采用主体默认。
- 基数与比例分别解析，不能因为只覆盖基数就丢失默认比例。
- 员工页面展示当期实际生效的基数、比例和来源，支持查看与维护例外记录。

## 4. 导入设计

### 工资方案导入

沿用工资方案导入能力，统一为工号、姓名（可选）、固定月薪、开始月份、结束月份（可选）、备注；导入后直接出现在对应员工展开的工资方案列表。有效期校验与手工维护相同，同一员工的导入与手工记录共同检查重叠。

### 社保公积金配置导入

现有“社保公积金金额表”改为一个“员工社保公积金配置表”导入入口。每行表示一名员工的一个缴费项目：

| 字段 | 要求 |
| --- | --- |
| 工号 | 必填，用于匹配当前主体员工 |
| 姓名 | 可选，用于核对与显示，不代替工号匹配 |
| 缴费项目 | 必填，例如对应社保项目或住房公积金 |
| 生效月份 | 必填，YYYY-MM |
| 截止月份 | 可选，留空表示持续有效 |
| 缴费基数 | 可选，填写则覆盖该项目默认基数 |
| 员工比例（%） | 可选，填写则覆盖该项目默认员工比例 |
| 单位比例（%） | 可选，填写则覆盖该项目默认单位比例 |

- 基数、员工比例、单位比例至少填写一项；其他字段继续跟随主体有效默认值。
- 未填写的配置字段不创建覆盖值。计算时缺失的必需字段不能变为 0。
- 自动归属当前解锁主体，不要求主体 ID；以工号匹配员工，姓名用于核对并提示不一致。
- 校验员工存在性、项目、月份、数值、比例范围及有效期冲突；同一员工、同一项目有效期不能重叠。
- 基数要求为正数；比例允许 0%–100%。是否符合实际申报口径仍由主体维护者核实，本次不内置自动获取地区费率。
- 保留批次来源、原始行号、撤销与恢复能力。撤销后回退主体默认；如果默认也未配置，明确阻止计算。
- 不接受旧“员工承担/单位承担金额”字段作为新计算输入，导入界面给出重新下载模板的提示。

## 5. 计算链路

1. 确定参算员工和工资所属月份；所属期与计划发放月分开保存。
2. 为每位员工匹配该所属月份唯一有效的工资方案，取得固定月薪；结合当期考勤、绩效、补扣款与计算规则计算应发。
3. 匹配相同所属月份有效的主体默认缴费配置及员工覆盖记录；工资有效期和缴费配置有效期分别解析。
4. 按员工覆盖优先、主体默认次之的顺序，逐项目、逐字段解析社保、公积金基数以及员工、单位比例。
5. 分别计算各项目员工、单位金额；按当前金额精度规则逐项目舍入到分，再分别汇总。
6. 员工承担汇总进入工资扣除及既有税务计算链路；单位承担汇总进入单位成本。
7. 保存计算快照：采用的工资方案及金额、基数、两方比例、逐项金额、汇总、有效期间、配置版本及来源批次。

单人试算与整批试算必须共用同一个计算模块。单人试算界面中的手填社保金额删除，改为只读基数/比例/结果及配置入口；后端也不能接受手填金额绕过配置。

普通工资规则不得再次覆盖或重复累加系统计算出的社保、公积金承担金额；已有冲突规则须提示处理，不静默执行。

整批试算在任一参算员工有效工资方案或必需缴费配置缺失时，列出姓名、工号、缺失项目，整批不保存部分结果。不得把缺失配置视为 0。

## 6. 页面与数据流调整

| 位置 | 变更 |
| --- | --- |
| 主体设置 | 新增独立的社保公积金默认配置入口，按项目和有效期间维护默认基数及员工/单位比例 |
| 员工与薪酬方案 | 员工行可展开，统一维护工资方案、社保及公积金列表；按查看月份显示最终基数、比例与继承来源，保留历史与未来方案 |
| 数据导入 | 工资与缴费配置统一有效月份模板；员工 Tab 可直接导入，导入页复用同一功能；保留预览、校验、撤销和恢复 |
| 工作台/上传状态 | 按最终有效配置完整度显示“已配置”，不再因没有金额文件显示缺失；显示采用主体默认、员工覆盖和配置缺失的人数 |
| 当月上传数据查询 | 按有效期间查询基数和比例；同时显示最终采用值和来源，避免把默认值误标为上传值 |
| 月薪计算/员工明细 | 按所属月取得工资方案及缴费配置，展示工资来源和社保、公积金逐项目基数、比例、金额；缺失时可定位员工 |
| 全员/单员工版本对比 | 增加逐项目承担金额及基数、比例变化；原有工资合计差异继续保留 |
| CSV/XLSX 导出 | 保持既定文件命名；在实际数据和计算说明中呈现社保、公积金金额及必要的基数、比例，不恢复主体/期间/内部 ID 等重复列 |
| 备份/日志 | 新配置随主体加密备份；配置保存、导入、撤销、恢复均留日志 |

对比时，金额相同但基数/比例不同，保留“金额一致”，额外提示“基数/比例变化”，不把配置差异混同为工资金额差异。延续蓝色按钮、橙色差异、绿色一致、紫色数据不完整及控件水平对齐规则。

## 7. 存储与旧数据处理

- 新增独立的主体配置与员工基数/比例记录；扩展统一工资方案的有效月份字段及查询接口，以非破坏方式更新数据库结构。
- 工资方案成为固定月薪的唯一新计算来源，不再同时从员工档案固定月薪字段取另一份工资。旧档案值仅在能明确有效期且不与现有方案冲突时转为初始方案；无法确定或有冲突时提示确认，不生成重叠方案。
- 已有工资方案保留；手工和导入记录统一纳入有效期检查。旧日级记录如涉及月中变更，列入待处理，不擅自改成月初。
- 保留现有主体、员工、导入批次和历史计算结果，不自动清空任何数据。
- 旧金额导入批次仅作为历史记录保留，不参与新的比例计算；不得反推基数或比例。
- 旧试算结果继续按原快照查看、对比和导出。没有基数/比例快照时标注为旧版金额结果，不伪造来源。
- 新配置只影响新试算；工资、比例、规则或基数变化后，对受影响期间提示需要重新试算。

## 8. 实施顺序与验证

| 步骤 | 实施范围 | 完成标准 |
| --- | --- | --- |
| 1 | 工资方案、主体默认、员工缴费配置的数据模型和接口 | 工资与缴费有效期分别解析，主体隔离、重叠校验和备份恢复测试通过 |
| 2 | 计算核心及快照 | 主体默认、员工导入、按字段部分覆盖、两方不同比例和舍入结果可独立核对 |
| 3 | 新导入模板与批次解析 | 导入/撤销/恢复、重复与缺失校验通过；金额字段不能成为新输入 |
| 4 | 主体设置、员工 Tab 行展开、三类历史列表及导入入口 | 主体默认独立维护；员工行独立展开，按查看月份显示工资/最终基数/比例与来源；未覆盖字段显示主体默认值；历史、当前、未来状态清晰 |
| 5 | 工资与缴费按月匹配、试算、状态、明细、对比、导出 | 不同有效期匹配正确；单人与整批结果一致；来源可追溯；旧快照不改变 |
| 6 | 回归验证与交付 | 构建通过、实际界面核对、新测试资料、版本及开发文档更新，再生成安装包与同步代码 |

重点验收场景：

1. 全员使用主体默认值，无需上传金额文件。
2. 仅两名员工导入特殊基数，其他员工仍采用主体默认。
3. 主体没有统一基数时，导入各自已核定基数并在有效期内跨月复用；缺失一人时明确阻断。
4. 社保各项目和公积金采用不同基数、比例及覆盖来源，各自计算正确。
5. 同项目不同员工、员工与单位采用不同比例；只覆盖一方时另一方默认值有效。
6. 0% 与未填写区分；无效数值、重叠配置、重复批次阻断。
7. 基数/比例调至新生效月份，旧月份匹配旧配置，历史已保存快照不变。
8. 使用虚构比例独立对账：基数 10,000、员工 2.5%、单位 5%，金额应为 250 和 500；该示例仅用于软件测试，不作为任何地区政策默认值。
9. 逐项目舍入再汇总，员工扣除、单位成本、税务链路及统计对比一致。
10. 旧金额导入不可影响新计算，旧结果仍可正常查看；备份恢复不丢失新配置。

11. 员工行展开后可同时查看工资、社保、公积金历史列表；更换查看月份后，主表当前值与展开区生效状态同步刷新。
12. 工资 1–6 月为 10,000、7 月起为 12,000；基数至 7 月为 8,000、8 月起为 9,000：6 月取旧工资旧基数，7 月取新工资旧基数，8 月取新工资新基数。
13. 工资方案缺失、有效期重叠或终止后无后续记录时，显示姓名/工号及对应月份并阻止计算。
14. 查询所属期为 10 月、计划发放月为 11 月时，工资和缴费配置均按 10 月选择。
15. 手工创建与导入同一员工重叠期间记录必须冲突；撤销导入后不能从另一份档案工资值静默补回。

16. 员工没有任何基数、比例覆盖时，员工页主表与展开列表显示当期主体默认配置，并标注“跟随主体默认”。
17. 员工只设置基数、只设置一方比例、同时设置多字段时，各字段分别显示正确的最终采用值和来源；0% 不回退为主体比例。
18. 主体默认比例在新月份调整后，未覆盖员工显示新比例；已有有效覆盖的员工保持自己的比例；历史已保存计算结果不改变。
19. 清除员工覆盖后恢复主体默认显示；若主体也未配置则显示缺失并阻止计算，不复制一份旧默认值继续使用。
